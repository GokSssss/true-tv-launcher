Файловый менеджер0.2 — системный выбор и провайдер
Это проектный контракт, не сообщение о готовом коде или проверенной совместимости.

Назначение
Приложение должно открываться по обычному запросу выбора файла из другого приложения на AndroidTV, включая устройства без штатного DocumentsUI. Выбранный документ должен реально читаться вызывающим приложением. Отдельно требуется выбор папки и места создания файла. Совместимость с конкретными эмуляторами проверяется практически, а не по наличию activity в manifest.

Две части
1. Собственный DocumentsProvider: корни доступных хранилищ, каталог/метаданные документов, открытие содержимого. Стабильные ID, тип, размер, имя, дата, только поддерживаемые операции. Корректные URI-допуски вместо выдачи всему приложению чужого корня. Для локальных файлов по возможности seekable descriptor, поскольку клиент может читать с произвольной позиции.
2. Окно выбора с тем же деревом и списком, но с режимом запроса клиента. Принимать стандартные неявные OPEN_DOCUMENT, GET_CONTENT, OPEN_DOCUMENT_TREE и CREATE_DOCUMENT. Учитывать MIME, допустимость нескольких файлов, предлагаемое имя и начальный URI. Регистрацию GET_CONTENT согласовать с провайдером, не создавать два одинаковых источника или рекурсию выбора себя через себя.

Результаты
Открытие — content URI доступного документа; несколько файлов — корректный ClipData при разрешённом множественном выборе. GET_CONTENT нужен для импорта/чтения; OPEN_DOCUMENT предусматривает долгосрочный доступ, который клиент может сохранить. Выбор папки возвращает tree URI, а создание — новый доступный для записи документ с обработкой совпадения имени. Передавать только необходимые read/write/persistable/prefix допуски, соответствующие операции и выбору. Не подменять результат голой строкой пути.

Интерфейс
Обычный режим: все файловые действия только в контекстном меню. В режиме выбора файлов верхняя кнопка «Выбрать» подтверждает результат запроса, это не меню копирования/удаления. Для выбора одного файла галочки множественного выбора скрываются; при EXTRA_ALLOW_MULTIPLE появляются галочки и счётчик. Пример третьего эскиза показывает запрос, разрешающий несколько файлов, а не обязательное поведение каждого эмулятора. Никаких нижних кнопок, до которых нужно пролистывать список. Отказ/Назад возвращает отмену без неожиданного открытия файла.

Границы
Стандартные неявные запросы можно проектировать как вход в собственный picker; приложение с явно заданным чужим системным компонентом не перенаправляется одним intent-filter. Возможны ограничения конкретной прошивки/клиента и директорий Android. Не обещать восстановление системного пакета/подписи или универсальность на всехTV. На Android9 локальный доступ требует корректных обычных разрешений; наличие провайдера не создаёт у него доступ к отсутствующему/закрытому хранилищу.

Приёмка после реализации
На отдельном эмуляторе: клиент вызывает каждый тип запроса, включая среду с отключённым только на тестовой машине DocumentsUI. Проверить выбор одного/нескольких файлов, содержимое через ContentResolver, MIME и метаданные, создание и запись, дерево и границы дерева. Сохранённый доступ проверять после завершения picker-процесса и перезапуска клиента. Проверить отмену, пустую папку/Вставить, недоступныйUSB, совпадения имён, длинный список и возврат к той же строке. Пульт: стрелки/OK/удержание/⋮/галочки, отсутствие двойного click при long press, выделение всех вне экрана. Никаких таких тестов пока не выполнено.
