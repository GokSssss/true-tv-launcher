Что изменено
Плюс и Замена открывают AppPicker/DialogFragment в уже открытом HomeActivity. Ни выбранное приложение, ни Settings, ни CatalogActivity при нормальном выборе не запускаются. Общий AppGrid с обычным каталогом: те же иконки, поиск, системные, русский/английский по системе, тема/обои. Commit/readback и фактически связанная новая плитка проверяются до закрытия только picker. Toast Добавлено отсутствует. Точный слот/поиск/незавершённое сохранение переживают пересоздание, общая очередь не меняет порядок записей, клики закрытого окна игнорируются. Back отменяет без записи, Home закрывает выбор.
После выбора завершается прежний жест OK; повторы/отдельные быстрые ИК-импульсы не запускают новую плитку. Новое намеренное OK после250мс тишины работает. Локальная защита выбора не перехватывает Home/чужие приложения и не переназначает ИК-драйвер.
Проблема двух Home воспроизведена на VM: обычный запуск создавал standard-task с Home+Settings, а системный Home — другой HOME-task. Отдельный собственный LauncherEntry с Theme.NoDisplay для LAUNCHER/LEANBACK направляет неявный MAIN+HOME только в свой пакет и закрывается; Home остаётся singleTask. Нормальные входы теперь один HOME-task. Прежний прямой non-HOME вход нормализуется с закрытием только своего устаревшего экрана/Task, настройки/файлы не удаляются. Возврат из службы управления использует тот же HOME Intent. Системная роль не назначается автоматически.
Backend217/TV Access/HomeDefaults/провайдер и операции файлов/экспертные/IR-команды не менялись. Wi-Fi по-прежнему заглушка. Изменение возврата ControlService проверено отдельно.
