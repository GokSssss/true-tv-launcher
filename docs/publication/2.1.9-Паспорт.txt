Изменения
Вернулась схема отдельного CatalogActivity → запись точного слота → finish → перерисовка Home при возврате. Нет AppPicker/DialogFragment, preference-driven ранней перерисовки, зависимости от Activity result или success-toast. Обычный выбор не запускает выбранное приложение и не открывает настройки. Сохранены durable commit/readback на worker и возможность назначать пакет без MAIN Activity. Существующие места не очищаются. При повторном Home/неизменённых данных Board сохраняется; единый HOME-entry218 остаётся без автоматической смены системной роли. Устаревший жестOK не запускает новую плитку.
Общий риск ранних версий: StatusWatch.start/stop обращались к Bluetooth/network Binder на UI-потоке. Теперь они только меняют таймер/эпоху; queries/profile binding — worker с ограниченной очередью, application context, слабая ссылка на UI, проверка эпохи/активности перед отображением. Прокси профилей общие для процесса, без bind/close на каждом переходе. При зависшей службе могут ждать индикаторы, UI не должен её ждать. Это устранённый риск, не доказанная причина белого OEM-экрана. Поллинг раз3сек пока экран активен; нет сохранения BT-адресов/названий.
Точная строка/label: Служебное управление приложениями (перезапуск и выключение). English: App service control (restart and stop). DefaultHome собственное меню сразу, статус resolve в фоне; отсутствующий OEM-экран объясняется и предлагается отдельно подтверждённый ADB. Нет ложного запуска текущего HOME под названием «выбор». Автоматических подключений/доступов/назначения роли нет.
Код файлового провайдера/операций/экспертных удалений/TV Access backend/IR не меняется. Wi-Fi отложен. Global hardware-rendering workaround не применялся, доказательств такой причины нет.
